# Neutripic Development Document

## 1. Service Overview

뉴트로픽(Neutripic)은 사용자의 건강 고민과 기본 프로필을 바탕으로 맞춤형 웰빙 영양 성분을 추천하는 AI 기반 서비스이다.

사용자는 개선하고 싶은 증상 또는 불편함을 설문 형태로 선택하고, 성별과 나이 등 기본 정보를 입력한다. 서비스는 식약처 공공 데이터인 건강기능식품 기능성 원료 인정현황을 가공한 데이터베이스를 기반으로 추천 후보 성분을 계산한다. 이후 AI는 추천 성분, 효능, 부작용, 주의사항, 추천 이유를 포함한 개인화 리포트를 생성한다.

뉴트로픽의 목표는 단순히 영양제를 나열하는 것이 아니라, 사용자의 여러 증상을 함께 고려하여 복용 부담이 적고 설명 가능한 핵심 성분 조합을 제안하는 것이다.

## 2. Core Service Concept

뉴트로픽은 다음 세 가지 가치를 중심으로 설계한다.

1. 식약처 공공 데이터 기반 추천
2. 다중 증상 기반 성분 우선순위 계산
3. AI를 활용한 개인 맞춤형 상담 리포트 생성

AI는 임의로 성분을 추천하지 않는다. 백엔드 스코어링 엔진이 먼저 식약처 기반 데이터에서 추천 가능한 성분 후보를 선별하고, AI는 이 검증된 컨텍스트 안에서 사용자에게 이해하기 쉬운 리포트를 작성한다.

## 3. Target Users

주요 사용자는 다음과 같다.

- 피로, 수면, 눈 건강, 장 건강, 면역, 피부, 스트레스 등 일상적인 건강 고민을 가진 사용자
- 영양제를 먹고 싶지만 어떤 성분이 필요한지 모르는 사용자
- 여러 증상을 동시에 관리하고 싶지만 과도한 영양제 복용은 피하고 싶은 사용자
- 추천 이유, 효능, 부작용, 주의사항을 함께 확인하고 싶은 사용자

## 4. Main User Flow

1. 사용자는 회원가입 또는 로그인한다.
2. 사용자는 추천 설문 페이지에서 개선하고 싶은 증상을 선택한다.
3. 사용자는 성별, 나이, 선택적으로 기저질환 또는 주의사항을 입력한다.
4. 백엔드는 선택된 증상과 사용자 프로필을 기반으로 추천 성분 후보를 계산한다.
5. 스코어링 엔진은 다중 증상에 공통으로 관여하는 성분에 높은 점수를 부여한다.
6. 과다섭취 위험이나 주의 성분을 필터링한다.
7. 최종 성분 목록과 식약처 기준 효능, 섭취량, 주의사항을 LLM 컨텍스트로 전달한다.
8. LLM은 개인 맞춤형 추천 리포트를 생성한다.
9. 사용자는 리포트를 확인하고 마이페이지에 저장한다.
10. 사용자는 게시판에서 건강 고민, 추천 후기, 영양제 경험을 공유할 수 있다.

## 5. Core Features

### 5.1 Symptom-Based Survey

사용자는 개선하고 싶은 증상을 체크박스 또는 카드 UI로 선택한다.

예상 증상 카테고리:

- 피로
- 수면
- 눈 건강
- 장 건강
- 면역
- 피부
- 스트레스
- 혈행
- 관절
- 기억력 또는 집중력

추가 입력 정보:

- 성별
- 나이
- 기저질환
- 임신 또는 수유 여부
- 복용 중인 영양제 또는 약물
- 알레르기 또는 피해야 하는 성분

초기 MVP에서는 성별, 나이, 증상 선택을 필수 입력으로 두고, 나머지는 선택 입력으로 확장할 수 있다.

### 5.2 Nutrient Scoring And Optimization Engine

사용자가 여러 증상을 선택했을 때, 서비스는 모든 성분을 단순 나열하지 않는다. 백엔드의 증상-성분 매핑 매트릭스를 기반으로 성분별 우선순위 점수를 계산한다.

작동 원리:

- 선택된 증상과 관련된 기능성 원료를 조회한다.
- 하나의 성분이 여러 증상에 동시에 관여하면 가중치를 높인다.
- 식약처 기준 기능성 내용, 일일 섭취량, 주의사항을 함께 조회한다.
- 과다섭취 위험, 중복 성분, 사용자 주의 조건을 반영해 후보를 필터링한다.
- 최종적으로 우선순위가 높은 핵심 성분 조합을 반환한다.

예시:

```text
사용자 선택 증상: 눈 건조, 피로

단순 추천:
- 눈 건강 성분 3개
- 피로 관련 성분 3개

뉴트로픽 추천:
- 두 증상에 함께 관여할 수 있는 핵심 성분 우선 추천
- 복용 부담을 줄인 조합 제안
```

목표는 "많이 추천하는 것"이 아니라 "적게, 근거 있게, 안전하게 추천하는 것"이다.

### 5.3 Generative Personalized Report

뉴트로픽의 리포트는 정형 표만 보여주지 않는다. LLM이 사용자 입력과 추천 성분 데이터를 바탕으로 약사 상담에 가까운 문체의 개인화 리포트를 생성한다.

LLM에 전달되는 컨텍스트:

- 사용자 프로필
- 선택 증상
- 최종 추천 성분
- 식약처 기능성 원료 인정 정보
- 효능 설명
- 일일 섭취량
- 섭취 시 주의사항
- 부작용 가능성

LLM의 역할:

- 추천 이유를 사용자 친화적으로 설명한다.
- 식약처 기준 문구를 이해하기 쉬운 상담 문장으로 변환한다.
- 효능, 주의사항, 부작용을 균형 있게 전달한다.
- 의학적 진단이나 치료처럼 오해될 수 있는 표현을 피한다.

리포트 예상 구성:

- 사용자 입력 요약
- 핵심 추천 성분 목록
- 성분별 추천 이유
- 기대할 수 있는 기능성
- 섭취 시 주의사항
- 부작용 가능성
- 생활 습관 관리 팁
- 건강 정보 제공 목적의 면책 안내

### 5.4 Report Save And My Page

생성된 리포트는 사용자의 마이페이지에 저장된다.

마이페이지 기능:

- 저장된 리포트 목록 조회
- 리포트 상세 조회
- 생성일 기준 정렬
- 선택 증상 기준 필터링
- 리포트 삭제

추후 확장 기능:

- 이전 리포트와 새 리포트 비교
- 관심 성분 즐겨찾기
- 복용 기록 또는 체크인 기능

### 5.5 Community

사용자는 게시판을 통해 건강 고민, 영양제 경험, 추천 후기 등을 공유할 수 있다.

기본 기능:

- 게시글 목록 조회
- 게시글 상세 조회
- 게시글 작성
- 게시글 수정
- 게시글 삭제
- 댓글 작성 및 삭제

게시판 예시 카테고리:

- 자유 게시판
- 영양제 후기
- 건강 고민
- 추천 리포트 공유

### 5.6 Coupang Product Search

사용자가 추천 리포트에서 영양 성분을 확인한 뒤, 해당 성분명으로 쿠팡 상품을 검색하여 인기순 상위 상품을 확인할 수 있다.

작동 방식:

- 추천 리포트에서 최종 추천 성분명을 추출한다.
- 백엔드는 성분명을 검색어로 사용하여 쿠팡 API를 호출한다.
- 쿠팡 검색 결과를 인기순 또는 랭킹 기준으로 정렬한다.
- 상위 5개 상품을 제품 카드 형태로 프론트엔드에 전달한다.

제품 카드 표시 정보:

- 상품명
- 상품 이미지
- 가격
- 상품 링크
- 판매처 또는 브랜드 정보
- 쿠팡 내 정렬 기준 또는 랭킹 정보

주의사항:

- 쿠팡 API Key와 Secret은 반드시 서버 환경 변수로 관리한다.
- 프론트엔드에서 쿠팡 API Key를 직접 사용하지 않는다.
- 추천 리포트의 성분 추천과 상품 검색 결과는 분리해서 보여준다.
- 상품 카드는 구매 편의를 위한 참고 정보이며, 특정 제품의 의학적 효능을 보장하지 않는다.
- 제휴 링크를 사용하는 경우 사용자가 알 수 있도록 고지한다.

## 6. System Architecture

뉴트로픽은 프론트엔드, Django 백엔드, AI 리포트 생성 레이어로 구성한다.

```text
[Frontend]
  - 설문 UI
  - 추천 결과 화면
  - 마이페이지
  - 게시판
        |
        v
[Backend - Django REST API]
  - 사용자 인증
  - 증상-성분 매핑 조회
  - 스코어링 엔진
  - 과다섭취 및 주의사항 필터링
  - 리포트 저장
  - 게시판 API
        |
        v
[AI Layer]
  - 최종 성분 목록 수신
  - 식약처 기준 텍스트 수신
  - LLM 프롬프트 구성
  - 개인 맞춤형 리포트 생성
        |
        v
[External APIs]
  - LLM API
  - Coupang product search API
        |
        v
[Database]
  - 사용자
  - 증상
  - 기능성 원료
  - 증상-성분 매핑
  - 추천 리포트
  - 게시글 및 댓글
```

## 7. Data Flow

```text
1. 사용자 입력
   - 나이, 성별, 증상 선택

2. 백엔드 스코어링
   - 증상-성분 매핑 테이블 조회
   - 다중 증상 교집합 성분 가중치 계산
   - 과다섭취, 중복, 주의 조건 필터링

3. LLM 컨텍스트 구성
   - 사용자 프로필
   - 최종 추천 성분
   - 식약처 효능 및 주의사항 텍스트

4. 리포트 생성
   - 개인화 추천 이유
   - 효능
   - 부작용
   - 주의사항
   - 생활 습관 팁

5. 쿠팡 상품 검색
   - 추천 성분명을 검색어로 사용
   - 인기순 상위 5개 상품 조회
   - 상품명, 이미지, 가격, 링크 제공

6. 최종 출력 및 저장
   - 추천 리포트 화면 표시
   - 추천 성분별 상품 카드 표시
   - 사용자가 저장하면 마이페이지에 보관
```

## 8. Differentiation

### 8.1 Safety Guard

사용자가 여러 증상을 선택하더라도 특정 영양소가 과도하게 추천되지 않도록 제어한다.

예:

- 아연
- 비타민 A
- 철분
- 지용성 비타민

초기 단계에서는 식약처 데이터에 포함된 섭취 시 주의사항과 일일 섭취량 정보를 우선 활용한다.

### 8.2 Explainable Recommendation

추천 결과는 단순 목록이 아니라 "왜 이 성분이 나에게 필요한지"를 설명한다. 사용자는 추천 이유, 근거 데이터, 주의사항을 함께 확인할 수 있다.

### 8.3 RAG-Based AI Report

LLM은 자체 지식만으로 답하지 않고, 백엔드가 선별한 식약처 기반 데이터만 컨텍스트로 받아 리포트를 작성한다. 이를 통해 환각 가능성을 줄이고, 추천 근거를 명확하게 유지한다.

### 8.4 Extensible Mapping Structure

증상-성분 매핑 테이블을 중심으로 설계하면, 추후 국내 제품 데이터, 해외 성분 데이터, 사용자 복용 기록 등을 추가하더라도 기존 추천 구조를 크게 바꾸지 않고 확장할 수 있다.

## 10. MVP Scope

초기 MVP는 다음 범위로 제한한다.

- 회원가입, 로그인, 로그아웃
- 증상 선택 설문
- 성별, 나이 입력
- 식약처 기반 기능성 원료 DB 구축
- 증상-성분 매핑 기반 추천 점수 계산
- LLM 기반 리포트 생성
- 쿠팡 API 기반 추천 성분 상품 검색
- 성분별 인기순 상위 5개 상품 카드 표시
- 리포트 저장 및 마이페이지 조회
- 게시판 CRUD
- 댓글 기능
- RESTful API 설계

초기 MVP에서 제외하거나 후순위로 둘 수 있는 기능:

- 결제
- 복용 알림
- 병원 또는 약국 연계
- 고도화된 약물 상호작용 분석
- 해외 직구 성분 데이터 연동

## 11. Safety And Disclaimer

뉴트로픽은 질병을 진단하거나 치료하는 서비스가 아니다. 추천 리포트에는 건강 정보 제공 목적임을 명확히 표시해야 한다.

필수 안내:

- 본 리포트는 건강 정보 제공 목적이다.
- 질병 진단, 치료, 처방을 대체하지 않는다.
- 임신, 수유, 만성질환, 복용 중인 약물이 있는 경우 전문가와 상담해야 한다.
- 특정 성분 섭취 후 이상 반응이 있으면 복용을 중단하고 전문가와 상담해야 한다.
- 쿠팡 상품 검색 결과는 구매 참고 정보이며, 뉴트로픽이 특정 상품의 치료 효과를 보장하지 않는다.
